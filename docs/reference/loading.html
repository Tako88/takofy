    Loading states

    Concept · 4 states · no spinners

    Nothing in this client spins. When the catalogue is late, the interface keeps the shape of what is coming, counts what it already holds, and reports it in the same mono voice it uses for a bitrate. Four states are documented here; the first one is live.

    02Tracklist, rows still in flight

    2.75 rem rows · no reflow

    Skeleton 0 of 6 rows loaded

    The placeholder rows keep the list density's own metrics — the same row height, the same 1px seam, the same index and duration gutters — so the tracklist does not jump when titles land. On a phone the album column is dropped here exactly as it is dropped in a resolved tracklist.

    03Transport, buffering

    green stays off

    Slow Tide · 320 kbps 0:07 loaded · 0:12 to resume

    7 s buffered playhead 0:00, stationary

    Playback cannot begin piecemeal, so the transport refuses to pretend: the playhead sits at 0:00 and the accent stays off until a full fragment lands. The front edge of the buffered span keeps a slow breath — that is the difference between a stream still arriving and one that has stalled.

    04Progress, counted or open

    16 fragments · tabular figures

    Same wait, two denominators
    Manifest known 6/16

    Six of sixteen fragments are held. A counted bar is a claim you can check: the number is the same one the status line speaks, and it is set in tabular figures so the meter never twitches as the digits change.

    Manifest unknown —

    Before the catalogue answers there is no denominator, so the trace stops claiming one: a single dim band crosses the track and carries no number. Inventing a percentage here would be a lie the user can catch.

    Loading system for the Takofy concept — see also the search reference and art credits. Placeholders reuse the resolved components' metrics (row heights, seams, square art), and motion is limited to one sheen, one breathing edge and one sweeping band.
