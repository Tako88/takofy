    Search reference

    8 decisions · static specimens

    The search input, decided. The fields on this page are real controls; the menus are static specimens of the states they produce — there is no index behind this page, so typing here will not query anything.

    01Field, in three states

    border only · 3 states

    Empty

    The placeholder names what the index actually holds. It is not a question the client cannot answer, and it is not the word “Search” echoed back at you from inside a search field.

    Focused, typing

    The border goes bone and nothing else moves: no glow, no icon swap, no width change. The input is real, so the caret is real. Results start at the first character; focus alone opens nothing.

    With text

    The clear control sits inside the field's own box, at its right edge, 4px from the border. Clearing therefore never changes the field's width — and never moves the menu that hangs off it. Escape does the same thing without the pointer.

    Same width as the field, 6px below it, 3px radius, one hairline border plus the app's largest shadow. Rows are 44px: a 36px cover, the title over its owner, and no kind tag — the band label already said what kind this is, and a tag repeating the word you just read is a column spent on nothing. The menu answers in three bands, always in this order: tracks, then albums, then artists. Each heading is the app's head grammar at small size — a mono caps label with that band's share on the right: 3 of 20, the app's own showing-versus-total phrasing, so a band that is hiding something says so without spending a “more” row of its own. A band that shows everything prints its total alone. A hairline separates one band from the next, and bands are capped (three tracks, two albums, two artists) so the whole thing stays on one screen. The index answers tracks and nothing else: the album and artist bands are read off the same twenty, so an album row is the record a match sits on and an artist row counts how many of the twenty are theirs — which is also why no row here quotes a listener count the payload cannot carry. The highlighted row spends the space where the tag used to sit on the action glyph, so it can never disagree with what Enter does: play/pause for a track, a chevron for anything that opens. Playlists and shows are missing for the same reason rather than by oversight: the index returns tracks, so there is nothing to derive a playlist band from.

    03Highlight, hover, and the row you are hearing

    last device wins

    Active — Enter opens this

    • Slow Tide Vela Moreno

    The keyboard's row: a 2px bone rule at the margin, a lit background, and the action glyph at the right edge.

    Pointer, while the keyboard holds another row

    • Harbour Wall Vela Moreno · Slow Tide

    A 4% wash and a 1rem tick at the margin — nothing more. It never borrows the rule or the glyph, so there is exactly one place that says “this is what Enter will fire”.

    This is the track you are hearing

    • Slow Tide Vela Moreno · Slow Tide

    The accent rule at the margin, and the equaliser in place of the action glyph. If the arrows land on this row as well, the accent stays — identity beats focus — and the glyph becomes pause.

    Which one wins when they disagree: the last device to move. Move the pointer and it takes the rule; press an arrow and the rule returns to the keyboard, leaving the row under the cursor as a wash and a tick. Enter always fires the ruled row. A click fires whatever it lands on, which is precisely why the pointer's row must never look selected.

    04The floor of the list

    1 band · 1 action

    • Artists 2 of 4

      • The Rookery 5 tracks
      • Vela Moreno 8 tracks
    • See more results for “harbour”

    Each band is capped, so the menu always ends mid-catalogue — here, on the second artist — and then comes a row that is an action: See more results for “harbour”. Without it a truncated band would be a dead end: the results page would be reachable only by pressing Enter on the right row, a keyboard-only route. It is a full 44px row, it speaks in the app's sentence case with the query in bone — a voice no band label uses — it takes the same highlight, and it is the only row without a cover. When no band is capped nothing is left over, so the action row is not rendered at all.

    05Over the page

    no scrim · z 40

    Menuz 40 · escapes the top bar
    Top barstatic · no clip
    View contentscrolls under, undimmed
    App paneloverflow hidden · radius 4

    The menu is a lens, not a mode: no scrim, no blur, no dimming of the page beneath — the covers in section 02 stay at their normal brightness while seven results float over them. It is not clipped by the top bar, which is static and has no overflow of its own; it crosses that hairline and is stopped only by the app panel's rounded frame. On a phone that panel is the viewport, so the viewport edge is where the list ends.

    One kind per block, and each block wears the grammar it already has everywhere else in the app: the tracks come as a tracklist — and the Album column is honest again, because the block is tracks only, which is exactly what the mixed list could not say — while albums and artists come as the card grids a shelf uses. The index answers twenty tracks and stops, so the page says so once, at the top: a hard cap that stays quiet reads as the whole catalogue. Ten rows, then one control that asks for the rest and then takes itself away — a request, not a switch, so it never collapses back, and a new query starts at ten again. The other two bands are read off all twenty, never off the ten on screen: computed from what is visible, they would grow underneath you the moment the list expanded and move the page while you were reading it. That is also what they can honestly claim — the album a match sits on, and how many of the twenty an artist accounts for; no listener counts, because a track payload has none. Every band caps at ten, rows or cards, with the same reveal, so the page has one rule rather than three. Each band keeps its size in the head's right slot — 10 of 20 is the same grammar as the menu's bands. Nothing where the album band would be: a query has no artwork to tint from. In a narrower window the album column is the first thing the track block gives up; at phone width the artist wraps under the title, exactly as a playlist does, and the grids fall to two columns.

    The specimen draws the first ten rows and stops at the control, because that is the state every query arrives in.

    At rail width the field is the rail: 20rem minus the drawer control and the nav cluster. The menu follows the field exactly and the query in the action row truncates instead of wrapping. Grouping costs nothing at this width, which is the point of moving the kind into a heading: a heading is a word, not a column, so there is no longest cell to measure and nothing to drop when the field narrows. Rows keep their 44px height — this is where a row is never allowed to lose its target size, only a column it does not need.
